## POST /api/v1/login

Ставит задание на вход.

### Тело запроса

| Поле | Тип | Обязательно | Ограничения | Смысл |
|---|---|---|---|---|
| `login` | строка | да | 1…128 символов | имя пользователя |
| `password` | строка | да | 1…256 символов | пароль |
| `job_id` | строка | нет | ≤ 64 символов | собственный идентификатор для идемпотентности |
| `wait_seconds` | число | нет | 0…120, по умолчанию 0 | сколько ждать результат в этом же запросе |

```bash
curl -X POST http://127.0.0.1:8080/api/v1/login \
  -H "Content-Type: application/json" \
  -d '{"login":"demo","password":"secret","wait_seconds":30}'
```

### Ответ

Всегда содержит `job_id` и `state`:

| `state` | Когда |
|---|---|
| `QUEUED` | задание принято и ждёт воркера |
| `RUNNING` | воркер уже выполняет |
| `DONE` | результат готов (только при `wait_seconds > 0`) |

```json
{"job_id": "9c1f4f0e", "state": "DONE", "status": "SUCCESS", "detail": ""}
```

Если `wait_seconds` истёк раньше, чем появился результат, вернётся `QUEUED`
или `RUNNING` — дальше опрашивайте `GET /api/v1/jobs/{id}`.

## GET /api/v1/jobs/{id}

Возвращает полное состояние задания.

```bash
curl http://127.0.0.1:8080/api/v1/jobs/9c1f4f0e
```

### Ответ

| Поле | Тип | Смысл |
|---|---|---|
| `job_id` | строка | идентификатор |
| `login` | строка | имя пользователя |
| `state` | `QUEUED` / `RUNNING` / `DONE` | состояние в очереди |
| `status` | строка или `null` | итог выполнения, см. таблицу статусов |
| `step` | строка или `null` | на каком шаге остановились |
| `detail` | строка или `null` | пояснение (код ответа платформы, причина) |
| `cookies` | массив | полученные cookie (имя, значение, домен, путь, `httpOnly`) |
| `challenge_passed` | логическое | была ли пройдена проверка |
| `attempts` | число | израсходовано попыток |
| `elapsed_ms` | число или `null` | длительность, миллисекунды |
| `retry_after` | число или `null` | рекомендуемая пауза, секунды |

Пример успешного задания:

```json
{
  "job_id": "9c1f4f0e",
  "login": "demo",
  "state": "DONE",
  "status": "SUCCESS",
  "step": "verify",
  "detail": "",
  "cookies": [
    {"name": ".ROBLOSECURITY", "value": "<redacted>", "domain": ".roblox.com",
     "path": "/", "httpOnly": true}
  ],
  "challenge_passed": false,
  "attempts": 1,
  "elapsed_ms": 2684,
  "retry_after": null
}
```

Замечание: значения cookie в ответе — действующий секрет. API по умолчанию
слушает `127.0.0.1`; не выставляйте его наружу без аутентификации.

## GET /healthz

Живость и состояние пула.

```json
{
  "ok": true,
  "queue_depth": 12,
  "workers": 4,
  "profiles": {"free": 8, "busy": 2, "cooldown": 3, "flagged": 0},
  "stats": {"SUCCESS": 120, "CHALLENGE_FAILED": 40},
  "version": "1.0.0"
}
```

`workers` берётся из таблицы воркеров по пульсу (окно 30 с), а не из
конфигурации: так видно реально живые процессы.

## GET /metrics

Метрики в формате Prometheus.

| Метрика | Тип | Смысл |
|---|---|---|
| `login_flow_seconds` | histogram | длительность обмена |
| `login_attempts_total` | counter | попытки по исходам |
| `jobs_by_status` | gauge | задания по статусам |
| `jobs_in_state` | gauge | задания в состояниях |
| `browser_bytes_total` | counter | трафик браузерного узла |
| `browser_sessions_total` | counter | число браузерных сессий |

Метрики воркеров — на отдельном порту (`SPK_METRICS_PORT`, по умолчанию
`9090`).

## Статусы результата

| Статус | Значение | Повторяется |
|---|---|---|
| `SUCCESS` | сессия получена и подтверждена | нет, финальный |
| `BAD_CREDENTIALS` | неверная пара | нет, финальный |
| `MANUAL_REQUIRED` | нужен ручной шаг (2FA и подобное) | нет, финальный |
| `CHALLENGE_FAILED` | платформа требует проверку | да |
| `PROXY_ERROR` | сетевой отказ профиля | да, попытка не расходуется |
| `RATE_LIMITED` | сработал лимит частоты | да |
| `INVALID_SESSION` | сессия не подтвердилась | да |
| `INTERNAL_ERROR` | внутренняя ошибка | да |

## Шаги выполнения

| Шаг | Что происходит |
|---|---|
| `csrf` | согласование токена запроса |
| `exchange` | сам вход |
| `challenge` | прохождение проверки |
| `retry` | повтор после проверки |
| `verify` | подтверждение сессии контрольным запросом |

`step` в ответе показывает, где задание остановилось, — это ускоряет
разбор неудач.

## Ошибки

| Код | Причина | Тело |
|---|---|---|
| `400` | тело не прошло валидацию | `{"detail": "..."}` |
| `404` | задание не найдено | `{"detail": "job not found"}` |
| `422` | неверные типы полей | стандартный ответ pydantic |
| `500` | внутренняя ошибка | `{"detail": "internal error"}` |

Пример проверки валидации:

```bash
curl -i -X POST http://127.0.0.1:8080/api/v1/login \
  -H "Content-Type: application/json" -d '{"login":"","password":""}'
```
