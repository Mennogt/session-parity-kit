# 02. Стандарты кода

## Общее

- Python 3.11, FastAPI, Redis, Playwright, `curl_cffi`.
  Отступление от стека — только с обоснованием абзацем в README.
- Типизация обязательна. `mypy` в CI, без подавлений в основном коде.
- Конфиг типизирован (pydantic-settings) и валидируется **на старте**.
  Некорректный конфиг — падение с внятным сообщением, а не работа в полсилы.
- Секреты только из окружения. В репозитории — `.env.example` без значений.

## Запрещено в основном коде

- `pass`, `TODO`, `NotImplementedError`, заглушки.
- «Mock вместо сети» — тесты могут мокать, продукт нет.
- Упрощённые версии шага под предлогом «потом доделаем».
- `sleep` как механизм синхронизации. Ожидание — по условию с таймаутом.
- Голые `except:` и проглатывание ошибок.
- Глобальное состояние, разделяемое между воркерами.

## Обязательно для каждого внешнего вызова

1. Явный таймаут (connect + read).
2. Обработка сетевой ошибки и ошибки протокола отдельно.
3. Лог с `job_id`, шагом, длительностью, кодом ответа.
4. Классификация в ровно один статус из `ref/statuses.md`.
5. Отсутствие секретов в логе (пароль, cookie-значения маскируются).

## Структура репозитория

```
api/            HTTP-слой
worker/         пул, аренда, исполнение
profiles/       пул профилей, health-check, карантин
challenge/      абстракция провайдера + реализации
flow/           шаги эталонной последовательности
queue/          транспорт и состояние
obs/            логи, метрики, трейсинг
probes/         разведочные скрипты (M0)
bench/          нагрузочный CLI (M3)
fixtures/       сырые ответы
docs/           FINDINGS.md, PERF.md
```

## Качество

- Юнит-тесты на классификацию ошибок и на парсинг форм ответа.
- Интеграционный тест на один поток с реальной сетью, помеченный как
  требующий профиля.
- Ни один PR не оставляет репозиторий в нерабочем состоянии.

## Коммиты и отчёты

Формат отчёта после каждого шага:

```
## M<N>
Сделано: ...
Проверено: <чем именно, какая команда, какой результат>
Осталось: ...
Блокеры: ...
```
