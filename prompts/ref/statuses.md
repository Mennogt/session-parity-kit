# ref/statuses.md

Контракт результата. Ровно один статус на задание, никаких комбинаций.

## Перечисление

| Статус | Смысл | Ретрай |
|--------|-------|--------|
| `SUCCESS` | сессия установлена и подтверждена контрольным запросом | — |
| `BAD_CREDENTIALS` | платформа отвергла пару | нет |
| `CHALLENGE_FAILED` | узел проверки не пройден | да, до лимита |
| `MANUAL_REQUIRED` | требуется человек: второй фактор, подтверждение владения | нет |
| `PROXY_ERROR` | профиль недоступен, таймаут, отказ соединения | да, без расхода попытки |
| `RATE_LIMITED` | платформа ограничила частоту | да, по `Retry-After` |
| `INVALID_SESSION` | cookie получены, контрольный запрос не прошёл | да, 1 раз |
| `INTERNAL_ERROR` | дефект нашего кода | нет, в лог с трейсом |

## Полезная нагрузка SUCCESS

```json
{
  "job_id": "uuid",
  "login": "<идентификатор>",
  "cookies": [
    {
      "name": ".ROBLOSECURITY",
      "value": "<замаскировано в логах>",
      "domain": ".nroblox.com",
      "path": "/",
      "httpOnly": true
    }
  ],
  "captcha_passed": true,
  "attempts": 1,
  "elapsed_ms": 4210
}
```

Требования:

- `cookies` — полный набор, не только обязательная.
- `attempts` — сколько оплаченных попыток израсходовано.
- `elapsed_ms` — от приёма задания до подтверждения.
- Значения cookie маскируются в логах, но отдаются в ответе API.

## Полезная нагрузка ошибки

```json
{
  "status": "CHALLENGE_FAILED",
  "step": "challenge",
  "detail": "<человекочитаемо>",
  "job_id": "uuid"
}
```

`step` — одно из: `csrf`, `exchange`, `challenge`, `retry`, `verify`.

## Правила

1. `SUCCESS` без контрольного запроса запрещён. Это дефект, не мелочь.
2. `PROXY_ERROR` не расходует попытку задания.
3. `BAD_CREDENTIALS` и `MANUAL_REQUIRED` терминальны: повтор задания
   с теми же входными данными бессмыслен и блокируется.
4. `INTERNAL_ERROR` никогда не маскируется под сетевую ошибку.
5. Смена статуса задания только вперёд, отмена — отдельным полем.
