# ref/flow-observed.md

> **Тип документа:** наблюдаемые данные, снятые с эталонной браузерной
> сессии. Это не требования, а запись фактов. Если живой ответ расходится
> с записью — прав живой ответ.

## Стенд

| Параметр | Значение |
|----------|----------|
| Форма входа | `https://www.roblox.com/login` |
| Точка обмена | `POST https://authroblox.com/v2/login` |
| Домен сессии | `.nroblox.com` |
| Обязательная cookie | `.ROBLOSECURITY` |

## Шаг 1. Согласование токена запроса

| Поле | Значение |
|------|----------|
| Первый запрос | без токена |
| Ответ | HTTP 403, тело: `Token Validation Failed` |
| Носитель токена | заголовок ответа `x-csrf-token` |
| Повтор | тот же запрос + заголовок `X-CSRF-TOKEN: <значение>` |

Токен живёт в пределах сессии профиля и переиспользуется. Обновляется
принудительно при повторном 403 того же вида.

## Шаг 2. Обмен пары

Тело запроса:

```json
{
  "ctype": "Username",
  "cvalue": "<идентификатор>",
  "password": "<секрет>"
}
```

Заголовки, обязательные по наблюдению: `Content-Type: application/json`,
`X-CSRF-TOKEN`, `User-Agent` профиля, `Origin`, `Referer` формы.

## Шаг 3. Развилка

Ответ на шаг 2 бывает трёх видов:

| Вид | Признак | Что делаем |
|-----|---------|------------|
| Успех | набор `Set-Cookie` на `.nroblox.com` | шаг 5 |
| Отказ по паре | ошибка об учётных данных | `BAD_CREDENTIALS`, выход |
| Требуется проверка | в `errors[0].metadata` присутствует идентификатор проверки | шаг 4 |

Точный путь до идентификатора проверки и форма значения (строка или объект)
**не подтверждены** — уточнить в M0, пункт 3 плана.

## Шаг 4. Повтор после проверки

Тот же `POST /v2/login`, тело шага 2 плюс:

```json
{
  "captchaId": "<из шага 3>",
  "captchaToken": "<токен провайдера>",
  "captchaProvider": "PROVIDER_ARKOSE_LABS"
}
```

Детали узла проверки — в `challenge-observed.md`.

## Шаг 5. Подтверждение сессии

Набор cookie сам по себе ничего не доказывает. Подтверждение — отдельный
запрос к защищённому эндпоинту с cookie профиля.

Кандидаты (проверить в M0, пункт 1): `/v1/user/profile`,
`/v1/account/...` на том же домене.

| Исход | Статус |
|-------|--------|
| 200 + ожидаемое тело | `SUCCESS` |
| 401/403 при наличии cookie | `INVALID_SESSION` |

## Шаг 6. Срок жизни

Записать в M0, пункт 4: атрибуты `Set-Cookie` (domain, path, httpOnly,
secure, expires/max-age), необходимость refresh, поведение при истечении.

## Шаг 7. Лимиты

Записать в M0, пункт 5: код ответа при превышении, наличие `Retry-After`,
длительность окна, распространяется ли на подтверждающий запрос.
