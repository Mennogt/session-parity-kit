## Когда показывается

Не детерминировано. Зависит от профиля, отпечатка, истории профиля
и решений на стороне платформы. Сервис обязан одинаково корректно
обрабатывать оба исхода.

## Детект

Ответ на обмен пары содержит ошибку, в `errors[0].metadata` которой
присутствует идентификатор проверки (`captchaId`). Точную форму значения
(строка либо объект с полями) подтвердить в M0.

## Установочный вызов — открытый вопрос

Не подтверждено, требуется ли предварительный вызов вида
`GetSessionDetails` / `fc/gc` до получения токена, и какие поля он
принимает. M0 обязан это выяснить и записать сюда.

Пока не выяснено — реализация проходит узел через браузерный контекст,
как живой клиент, без ручной сборки внутренних вызовов провайдера.

## Прохождение

Обязательные свойства реализации:

- **Интерактивно.** Открывается реальный браузерный контекст, узел
  проходится как человеком, так и браузером.
- **В контексте профиля.** Тот же прокси, тот же User-Agent, тот же
  отпечаток, та же cookie-банка. Иначе токен не примут.
- **С таймаутом.** Открытие, ожидание готовности, ожидание токена —
  каждый этап со своим таймаутом.
- **С гарантированной уборкой.** Контекст закрывается в `finally`. Сирота
  после падения — дефект.

## Выход узла

Токен провайдера → поле `captchaToken` в повторе обмена пары.

## Классификация отказов

| Ситуация | Статус |
|----------|--------|
| Узел не открылся, скрипт не загрузился | `CHALLENGE_FAILED` |
| Токен не выдан за отведённое время | `CHALLENGE_FAILED` |
| Токен выдан, платформа его отвергла | `CHALLENGE_FAILED`, профиль в карантин |
| Требуется почта/телефон/второй фактор | `MANUAL_REQUIRED` |

## Абстракция

```
ChallengeProvider.solve(context, profile) -> token | ChallengeError
```

Реализация по умолчанию — браузерная. Регистрация альтернативных
реализаций — по имени в конфиге, без правок вызывающего кода.
Ни одна реализация не получает предвычисленные токены.
