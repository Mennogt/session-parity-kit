# 04. План работ

Шаги выполняются по порядку. Перескакивать нельзя: каждый следующий
опирается на артефакты предыдущего.

## M0 — Разведка

Скрипты в `probes/` снимают реальные ответы целевой платформы:

- первый запрос без токена → ожидаемая ошибка валидации токена + заголовок
  с токеном;
- повтор с токеном и неверной парой → форма ответа;
- запрос, на который платформа отвечает узлом проверки → форма ответа;
- контрольный запрос к защищённому эндпоинту: что означает «сессия жива».

Сырые JSON сохраняются в `fixtures/`. На их основе — `docs/FINDINGS.md`.

**Открытые вопросы, на которые M0 обязан ответить:**

1. Какой эндпоинт подтверждает, что сессия жива, и какой у него ответ.
2. Нужен ли установочный вызов узла проверки перед выдачей токена, и какие
   поля он принимает.
3. Точный путь до идентификатора проверки в теле ошибки: строка или объект.
4. Как выглядит ответ при повторном запросе, когда проверка не требуется.
5. Форма и срок жизни cookie; нужен ли refresh.
6. Поведение при лимите запросов: код, наличие `Retry-After`, длительность
   окна.

**Выход:** `probes/` + `fixtures/` + `docs/FINDINGS.md`. Репозиторий
запускается.

## M1 — Один поток, end-to-end

Один воркер, один профиль, один аккаунт:

```
токен → запрос → детект проверки → прохождение → повтор → cookie → контроль
```

**Стоп-точка.** Показать результат: сырые шаги, длительности, подтверждение
сессии. Дождаться подтверждения перед M2.

**Выход:** рабочий скрипт + отчёт по шагам.

## M2 — Упаковка

- API из `03-components.md`.
- Очередь, пул воркеров, аренда.
- Слой профилей, аренда/возврат/карантин.
- Все статусы из `ref/statuses.md`, включая `INVALID_SESSION`.
- Идемпотентность по `job_id`.

**Выход:** сервис поднимается, принимает задания, отдаёт статусы.

## M3 — Нагрузочный контур

`bench` CLI: подаёт N заданий, считает фактический KPM и p95, пишет отчёт.

Замеры: 4 → 16 → 64 воркера. Зафиксировать точку, где рост перестаёт быть
линейным, и назвать причину (очередь, пул профилей, CPU, лимит платформы).

**Выход:** `bench/` + таблица замеров в `docs/PERF.md`.

## M4 — Гигиена ресурсов

- Закрытие браузерных контекстов в `finally`, без исключений.
- Очистка осиротевших процессов при старте воркера и при возврате профиля.
- Отсутствие роста памяти на длинной серии заданий.
- Прогон 10 000 заданий с замером `processes_orphaned_total` = 0.

**Выход:** метрики + подтверждение прогоном.

## M5 — Документация и упаковка

`docker-compose.yml`, `.env.example`, OpenAPI, README с инструкцией

**Выход:** репозиторий, который поднимается одной командой на чистой машине.
